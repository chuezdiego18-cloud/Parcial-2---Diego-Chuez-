Reglas que ayudan a diseñar mejor.

Las 8 reglas de oro de Shneiderman y las 10 heurísticas de Nielsen, con un ejemplo cada una.

Las 8 reglas de oro de Shneiderman

Ben Shneiderman las propuso para diseñar interfaces que se sientan claras y seguras de usar.

  1. Buscar la consistencia

    Acciones parecidas deben verse y funcionar de forma parecida en todo el sistema.

    Ejemplo: este sitio usa el mismo menú y footer en todas las páginas.

  2. Facilitar el uso universal

    El diseño debe servir a personas con distintas edades, habilidades y niveles de experiencia.

    Ejemplo: texto con buen contraste y un enlace para saltar al contenido.

  3. Dar retroalimentación informativa

    Cada acción de la persona debe tener una respuesta visible del sistema.

    Ejemplo: un botón que cambia de color al pasar el cursor.

  4. Diseñar diálogos con un final claro

    Las secuencias de pasos deben tener inicio, desarrollo y cierre, para que la persona sepa que terminó.

    Ejemplo: una pantalla de «Compra realizada» al terminar un pago.

  5. Prevenir errores

    El sistema debe evitar que la persona se equivoque y ayudarla a corregir si ocurre.

    Ejemplo: un campo de correo que avisa si falta el símbolo @.

  6. Permitir deshacer fácilmente

    Poder revertir una acción da tranquilidad para explorar sin miedo.

    Ejemplo: la opción «Deshacer» tras borrar un mensaje.

  7. Dar el control a la persona

    Quien usa el sistema debe sentir que lo dirige, no que el sistema decide por él.

    Ejemplo: poder pausar un video o cerrar una ventana emergente.

  8. Reducir la carga de memoria

    Es mejor mostrar las opciones a la vista que obligar a recordarlas.

    Ejemplo: un menú siempre visible con la página actual marcada.

Las 10 heurísticas de Nielsen

Jakob Nielsen las formuló para evaluar qué tan usable es una interfaz. Haz clic en cada una para ver el detalle.

1. Visibilidad del estado del sistema

La persona siempre debe saber qué está pasando.

Ejemplo: una barra de progreso al subir un archivo.

2. Coincidencia con el mundo real

El sistema debe hablar el lenguaje de quien lo usa, sin tecnicismos innecesarios.

Ejemplo: un ícono de carrito para las compras.

3. Control y libertad del usuario

Debe haber una salida clara cuando la persona se equivoca o cambia de opinión.

Ejemplo: las migas de pan para volver a la página anterior.

4. Consistencia y estándares

Lo que se parece debe comportarse igual, y se deben seguir las convenciones conocidas.

Ejemplo: el logo siempre lleva a la página de inicio.

5. Prevención de errores

Es mejor evitar el problema que mostrar un mensaje de error.

Ejemplo: pedir confirmación antes de eliminar algo importante.

6. Reconocer en lugar de recordar

Las opciones y la información deben estar visibles, para no cargar la memoria.

Ejemplo: un buscador que sugiere búsquedas recientes.

7. Flexibilidad y eficiencia de uso

El sistema debe servir tanto a principiantes como a personas expertas.

Ejemplo: atajos de teclado como Ctrl + C.

8. Diseño estético y minimalista

Cada elemento extra compite con lo importante, así que conviene mostrar solo lo necesario.

Ejemplo: una página con pocos colores y mucho espacio libre.

9. Ayudar a reconocer y corregir errores

Los mensajes de error deben explicar qué pasó y cómo solucionarlo, en lenguaje simple.

Ejemplo: «La contraseña debe tener al menos 8 caracteres».

10. Ayuda y documentación

Si hace falta ayuda, debe ser fácil de encontrar y de seguir.

Ejemplo: una sección de preguntas frecuentes.

Cómo aplica este sitio estas reglas

Orientación y control

El menú marca la página actual, las migas de pan permiten volver y el enlace del footer lleva de nuevo al inicio del contenido.

Consistencia y minimalismo

Todas las páginas comparten el mismo header, menú, footer y estilos, con pocos colores y tipografías.

Accesibilidad

Hay contraste alto, foco visible al navegar con teclado, textos alternativos en las imágenes y diseño adaptable a celular.
